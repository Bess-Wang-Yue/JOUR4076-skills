# 手繪線框圖轉原型

## 目標

設計決定由人在紙上做；這個 skill 只負責把手繪線框圖忠實地做成可以在手機和電腦上點擊試用的原型。

## 最重要的界線

- **忠於手繪。** 保留草圖的區塊、次序和元素。不要自行增加區塊或功能，不要調換次序，不要「優化」版面。草圖上看不清的地方，先問；問不到就在原型上標「？」。
- **不虛構客戶資料。** 收費、日期、地址、電話、服務名稱等，只用用戶提供的內容。沒有提供的，寫成 `【待填：費用】` 這類佔位文字。
- **不會真的提交。** 表格和查詢按鈕只顯示「原型示範：不會真的提交」，不連接任何真實地址或電郵。

## 工作流程

1. **讀圖。** 打開用戶提供的每一張草圖。
2. **複述，然後等確認。** 由上而下列出你從草圖讀到的區塊，例如：「1. 頂部：標誌＋選單按鈕；2. 大標題：『活動及報名』；3. 三張活動卡，每張有時間、費用、報名按鈕……」。同時問三件事，然後停下等用戶回覆：
   - 有沒有讀錯或漏掉的地方？
   - 每個區塊回應 Part A 哪一項發現（編號）？
   - 有沒有真實的文字內容要放進去？沒有就用佔位文字。
3. **製作原型。** 用戶確認後，以 `assets/template.html` 為基礎，寫一個獨立的 `index.html`：
   - 所有 CSS 和 JavaScript 寫在同一個檔案內，不用外部字體、圖庫或框架，離線也能打開。
   - 先照手機寬度（約 375px）設計，電腦上置中顯示；草圖本身是電腦版的，就照電腦版。
   - 多張草圖代表多個頁面時，做成同一檔案內可以互相點擊切換的頁面。
   - 預設中保真：灰階為主，一種強調色。用戶要求「加視覺」時才加顏色和細節。
4. **設計說明。** 在原型右下角放「設計說明」按鈕，按下顯示每個區塊的編號、設計決定，以及對應的 Part A 發現編號。用戶沒有提供的，寫「【待填】」，不要代為編寫理由。
5. **交代差異。** 交付時列出：原型和草圖不同的地方（如有）及原因；仍是佔位文字的地方；建議用戶用同一個任務重新測試一次。

## 基本無障礙要求

- 文字與背景對比至少 4.5:1（WCAG 1.4.3）。
- 正文字體不小於 16px。
- 圖片有替代文字；表格欄位有標籤。
- 按鈕和連結的可點擊範圍不小於 44 × 44px。

## 注意事項

- 不要提供多個版本讓用戶挑選，除非用戶要求。原型只有一個，就是草圖那一個。
- 用戶改了草圖，重新從第 1 步開始，不要在舊原型上猜測修改。
- 草圖照片太模糊時，請用戶重拍，並建議在紙上用粗筆寫清楚每個區塊的名稱。
